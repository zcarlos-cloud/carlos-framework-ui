## 三、命名规范

### 3.1 文件命名

| 类型       | 规范                  | 示例                                 |
|----------|---------------------|------------------------------------|
| Vue 组件   | kebab-case          | `app-provider.vue`                 |
| TS/JS 文件 | camelCase           | `common.ts`, `auth.ts`             |
| 目录       | kebab-case          | `global-breadcrumb`, `user-center` |
| 常量文件     | camelCase           | `app.ts`, `business.ts`            |
| 类型声明文件   | camelCase + `.d.ts` | `api.d.ts`, `app.d.ts`             |
| 子模块目录    | `modules/`          | 统一命名                               |
| 页面入口     | `index.vue`         | 每个视图目录下固定命名                        |

### 3.2 代码命名

| 类型         | 规范               | 示例                               |
|------------|------------------|----------------------------------|
| 组件名（代码）    | PascalCase       | `AppProvider`, `UserSearch`      |
| 函数/Hook    | camelCase        | `useTable`, `fetchLogin`         |
| 常量         | UPPER_SNAKE_CASE | `GLOBAL_HEADER_MENU_ID`          |
| Record 常量  | xxxRecord        | `themeSchemaRecord`              |
| Options 常量 | xxxOptions       | `themeSchemaOptions`             |
| 接口/类型      | PascalCase       | `PaginatingCommonParams`         |
| 枚举         | PascalCase       | `SetupStoreId`                   |
| 枚举成员       | PascalCase       | `App`, `Theme`, `Auth`           |
| API 函数     | fetch + 动词 + 名词  | `fetchGetUserList`, `fetchLogin` |
| Store      | useXxxStore      | `useAuthStore`, `useAppStore`    |

### 3.3 Vue 组件名规范

- 组件名必须为**多词组合**（除 `index`, `App`, `Register`, `[id]`, `[url]` 外）
- 模板中使用 **PascalCase** 引用组件（如 `<ASpace>`, `<UserSearch>`）
- 全局注册组件（Ant Design Vue）使用大写前缀 `A`，如 `AWatermark`
- 通过 `defineOptions({ name: 'ComponentName' })` 显式声明组件名

- UnoCSS attributify 顺序检查关闭：`unocss/order-attributify: off`

## 五、Vue 组件开发规范

### 5.1 SFC 结构

```vue
<script setup lang="ts">
// 1. 类型导入
import type { WatermarkProps } from 'ant-design-vue';

// 2. Vue / 库导入
import { computed } from 'vue';
import { ConfigProvider } from 'ant-design-vue';

// 3. 内部模块导入（按层级排序）
import { useAppStore } from '@/store/modules/app';
import { useThemeStore } from '@/store/modules/theme';
import { antdLocales } from '@/locales/antd';

// 4. 组件选项
defineOptions({
  name: 'App'
});

// 5. 逻辑代码
const appStore = useAppStore();
const themeStore = useThemeStore();

const antdLocale = computed(() => {
  return antdLocales[appStore.locale];
});
</script>

<template>
  <ConfigProvider :theme="themeStore.antdTheme" :locale="antdLocale">
    <AppProvider>
      <RouterView class="bg-layout" />
    </AppProvider>
  </ConfigProvider>
</template>

<style scoped></style>
```

### 5.2 导入顺序

1. `import type` 类型导入
2. 第三方库（Vue, Pinia, Ant Design Vue 等）
3. 内部 Hooks / Store / Utils（按 `@/store/`, `@/hooks/`, `@/utils/` 排序）
4. 同目录相对路径导入 `./modules/xxx.vue`

### 5.3 模板规范

- 使用 **PascalCase** 书写组件标签（`<HeaderBanner />` 优于 `<header-banner />`）
- 属性绑定使用双引号：`"value"`
- 自闭合组件无子元素时写为 `<Component />`
- 复杂渲染逻辑使用 TSX（`<script setup lang="tsx">`）

### 5.4 Props / Emits

优先使用 TypeScript 类型推导：

```typescript
// Props 定义
interface Props {
  /** 用户ID */
  userId?: number;
  /** 是否显示 */
  visible: boolean;
  /** 模式：create | edit | view */
  mode?: 'create' | 'edit' | 'view';
}

const props = withDefaults(defineProps<Props>(), {
  userId: 0,
  mode: 'create'
});

// Emits 定义
const emit = defineEmits<{
  submit: [data: UserFormData];
  cancel: [];
  'update:visible': [value: boolean];
}>();
```

- 复杂类型在 `typings/` 中声明
- Props 添加 JSDoc 注释说明用途
- Emits 使用类型定义而非字符串数组

### 6.2 Interface vs Type

| 场景   | 推荐          | 说明                         |
|------|-------------|----------------------------|
| 对象类型 | `interface` | 可扩展、可合并声明                  |
| 联合类型 | `type`      | `'active' \| 'inactive'`   |
| 工具类型 | `type`      | `Partial<T>`, `Pick<T, K>` |

```typescript
// 对象类型使用 interface
interface User {
  id: number;
  name: string;
}

interface Admin extends User {
  permissions: string[];
}

// 联合类型和工具类型使用 type
type Status = 'active' | 'inactive' | 'deleted';
type PartialUser = Partial<User>;
```

### 6.3 非空断言规范

尽量避免使用 `!` 非空断言，优先使用可选链和类型守卫：

```typescript
// 不推荐
const name = user!.name;

// 推荐：可选链 + 默认值
const name = user?.name ?? '';

// 推荐：类型守卫
if (user) {
  const name = user.name; // TypeScript 知道 user 不为 undefined
}
```

### 6.4 类型声明规范

使用 `declare namespace` 组织全局类型：

```typescript
declare namespace Api {
  namespace Common {
    interface PaginatingCommonParams {
      current: number;
      size: number;
      total: number;
    }

    type EnableStatus = '1' | '2';
  }

  namespace Auth {
    interface LoginToken {
      token: string;
      refreshToken: string;
    }
  }
}
```

### 6.3 路径别名

| 别名   | 指向       | 用途      |
|------|----------|---------|
| `@/` | `./src/` | 业务源码引用  |
| `~/` | `./`     | 项目根目录引用 |

## 七、状态管理规范（Pinia）

### 7.1 Store 定义

使用 **Composition API 风格**：

```typescript
import { ref, computed } from 'vue';
import { defineStore } from 'pinia';
import { SetupStoreId } from '@/enum';

export const useAuthStore = defineStore(SetupStoreId.Auth, () => {
  // State
  const token = ref(getToken());

  // Computed
  const isLogin = computed(() => Boolean(token.value));

  // Actions
  async function resetStore() {
    clearAuthStorage();
    token.value = null;
  }

  return {
    token,
    isLogin,
    resetStore
  };
});
```

### 7.2 Store ID 枚举

所有 Store ID 统一定义在 `src/enum/index.ts`：

```typescript
export enum SetupStoreId {
  App = 'app-store',
  Theme = 'theme-store',
  Auth = 'auth-store',
  Route = 'route-store',
  Tab = 'tab-store'
}
```

### 7.3 使用规范

- 使用 `ref` / `reactive` 定义状态
- 使用 `computed` 定义派生状态
- 使用 `effectScope` 管理副作用生命周期
- 命名导出：`useXxxStore`

### 8.3 API 函数定义

```typescript
import { request } from '../request';

/**
 * Login
 *
 * @param userName User name
 * @param password Password
 */
export function fetchLogin(userName: string, password: string) {
  return request<Api.Auth.LoginToken>({
    url: '/auth/login',
    method: 'post',
    data: {
      userName,
      password
    }
  });
}

/** Get user info */
export function fetchGetUserInfo() {
  return request<Api.Auth.UserInfo>({ url: '/auth/getUserInfo' });
}
```

## 十六、最佳实践

### 16.1 组件拆分

- 页面级组件放在 `views/[page]/index.vue`
- 页面子模块放在 `views/[page]/modules/`
- 通用组件放在 `components/common/`
- 高级业务组件放在 `components/advanced/`

### 16.2 状态管理

- 全局状态使用 Pinia Store
- 局部状态使用 `ref` / `reactive`
- 派生状态使用 `computed`
- 副作用使用 `effectScope` 管理生命周期

### 16.3 性能优化

**组件优化：**

- 使用 `v-if` / `v-show` 合理控制渲染
- 大数据列表使用虚拟滚动
- 图片使用懒加载
- 路由组件使用懒加载（由 Elegant Router 自动生成）
- 大数据对象使用 `shallowRef` 避免深层响应式
- 使用 `computed` 缓存计算结果

```typescript
// 大数据对象使用 shallowRef
const bigList = shallowRef([]);

// 组件懒加载
const HeavyComponent = defineAsyncComponent(() => import('./heavy-component.vue'));

// 使用 v-memo 缓存条件渲染
// <div v-memo="[user.id, user.status]">
//   {{ user.name }} - {{ user.status }}
// </div>
```

**网络优化：**

- 防抖处理频繁请求（搜索框等）
- 预加载关键资源

```typescript
import { debounce } from '@/utils/common';

const debouncedSearch = debounce(() => {
  loadData();
}, 300);
```

### 16.4 安全规范

**XSS 防护：**

- 优先使用 `v-text` 或 `{{ }}` 自动转义
- 避免使用 `v-html`，必须使用时应先净化

```vue
<template>
  <!-- 安全：自动转义 -->
  <div>{{ userInput }}</div>

  <!-- 危险：避免直接使用 -->
  <!-- <div v-html="userInput"></div> -->

  <!-- 必须使用 v-html 时，先净化 -->
  <div v-html="purifyHtml(userInput)"></div>
</template>
```

**敏感数据处理：**

- 禁止在前端代码中硬编码密钥、Token

}
