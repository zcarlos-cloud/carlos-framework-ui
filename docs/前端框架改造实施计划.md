# Carlos-UI 前端框架改造实施计划

> **版本**: v1.1
> **日期**: 2026-05-28
> **状态**: Phase 0 已完成
> **目标**: 完成前端基础框架与 Carlos Framework 后端的接口对齐与功能改造

---

## 1. 概述

本计划基于 `前后端对接实施计划.md` 的分析结果，针对前端 `carlos-framework-ui` 当前代码与后端实际接口的差异，梳理出需新增或改造的框架级功能清单。

**核心矛盾**：前端 service 层路径、字段名、返回结构与后端 Controller 实际实现存在系统性偏差，需逐一对齐。

**统一前缀方案（已实施）**：

Gateway 已配置统一前缀 `/manage-api`（`GatewayProperties.prefix` 默认值），通过 `PathPrefixFilter` 全局截掉此前缀后路由到各微服务。

**前缀由 `baseURL` 统一承载，接口 `url` 不再硬编码 `/manage-api`**：

- 开发环境（代理模式）：`proxyPattern` 为 `/manage-api`，axios `baseURL` 为 `/manage-api`，接口 `url` 只写后端 Controller 路径（如 `/auth/user/login`），Vite 代理 rewrite 去掉 `/manage-api` 后转发给单体应用
- 生产环境：`.env.prod` 中 `VITE_SERVICE_BASE_URL` 包含 `/manage-api`（如 `http://localhost:8080/manage-api`），axios `baseURL` 自动拼接前缀，Gateway `PathPrefixFilter` 截掉 `/manage-api` 后按路由规则转发

此方案下，后端 Controller 路径完全保持现状不变，前端 service 层 `url` 与后端 `@RequestMapping` 一一对应。

## 7. Gateway 统一前缀配置（已实施）

### 7.1 实际配置结论

| 配置项              | 实际值                               | 说明                                        |
|------------------|-----------------------------------|-------------------------------------------|
| Gateway 统一前缀     | `/manage-api`                     | `GatewayProperties.prefix` 默认值            |
| 前缀处理方式           | `PathPrefixFilter` (GlobalFilter) | 全局截掉 `/manage-api` 后路由，ORDER_FIRST (1000) |
| 路由过滤器            | `SelectStripPrefix=1`             | 仅对 Swagger/Knife4j 文档路径生效                 |
| carlos-auth 路由   | `Path=/auth/**,/oauth2/**`        | 已启用                                       |
| carlos-system 路由 | `Path=/sys/**,/app/**`            | Phase 0 已取消注释                             |
| carlos-org 路由    | `Path=/org/**`                    | Phase 0 已取消注释                             |

### 7.2 前端 Vite 代理配置（已实施）

```typescript
// build/config/proxy.ts
proxy[item.proxyPattern] = {
  target: item.baseURL,
  changeOrigin: true,
  rewrite: path => {
    // Gateway 统一前缀 /manage-api，开发环境直连单体应用时去掉此前缀
    if (item.proxyPattern === '/manage-api') {
      return path.replace(/^\/manage-api/, '');
    }
    return path.replace(new RegExp(`^${item.proxyPattern}`), '');
  }
};
```

**关键说明**：

- 开发环境：Vite 代理去掉 `/manage-api` 后发给单体应用，单体应用 Controller 直接匹配
- 生产环境：请求保留 `/manage-api` 发给 Gateway，`PathPrefixFilter` 截掉 `/manage-api` 后按路由规则转发
- `proxyPattern` 已从 `/proxy-default` 改为 `/manage-api`

### 7.3 后端 Gateway 路由配置（已实施）

```yaml
# carlos-gateway/src/main/resources/application.yml
spring:
  cloud:
    gateway:
      routes:
        -
          id: carlos-auth
          uri: lb://carlos-auth
          predicates:
            - Path=/auth/**,/oauth2/**
          filters:
            - SelectStripPrefix=1
        -
          id: carlos-system
          uri: lb://carlos-system
          predicates:
            - Path=/sys/**,/app/**
          filters:
            - SelectStripPrefix=1
        -
          id: carlos-org
          uri: lb://carlos-org
          predicates:
            - Path=/org/**
          filters:
            - SelectStripPrefix=1
```
