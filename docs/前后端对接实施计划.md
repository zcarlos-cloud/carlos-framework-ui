## 1. 项目概述

### 1.1 项目背景

本项目旨在将 **SoybeanAdmin** (Vue3 前端管理框架) 与 **Carlos Framework** (Spring Boot 后端框架)
进行深度整合，实现一套完整的企业级开发解决方案。

### 1.2 对接目标

| 目标      | 描述                                    |
|---------|---------------------------------------|
| 统一响应格式  | 前后端响应数据结构保持一致（已统一）                    |
| 完整认证流程  | 实现登录、Token刷新、登出功能                     |
| 动态权限路由  | 根据用户角色动态加载菜单路由                        |
| 用户角色管理  | 完整的RBAC权限管理功能                         |
| 枚举字典体系  | 后端枚举自动扫描，前端可动态获取使用                    |
| 通用字段标准化 | id/createTime/updateBy/status 等字段统一处理 |

## 3. 关键数据格式对照

### 3.1 响应结构对照

**后端当前格式** (`Result<T>`):

```json
{
  "success": true,
  "code": "00000",
  "msg": "操作成功",
  "data": { ... },
  "timestamp": 1710638258000,
  "details": null
}
```

**前端期望格式** (`App.Service.Response`):

```json
{
  "code": "00000",
  "msg": "操作成功",
  "data": { ... }
}
```

**结论**: 字段基本一致，后端 `Result` 多返回了 `success` / `timestamp` / `details` 字段，前端可直接使用 `code` / `msg` / `data`，无需额外适配。

### 3.2 字段映射表

| 后端字段      | 前端字段   | 后端类型    | 前端类型   | 处理方式         |
|-----------|--------|---------|--------|--------------|
| `code`    | `code` | String  | String | 一致           |
| `success` | -      | Boolean | -      | 前端使用 code 判断 |
| `msg`     | `msg`  | String  | String | 一致           |
| `data`    | `data` | T       | T      | 一致           |
| `details` | -      | Array   | -      | 仅校验错误时返回     |

### 3.3 响应码映射表

| 后端 Code | 场景       | 处理动作      |
|---------|----------|-----------|
| 00000   | 成功       | 正常处理      |
| A0001   | 未认证      | 跳转登录页     |
| A0002   | 无权限      | 显示无权限页面   |
| A0004   | Token 过期 | 自动刷新Token |
| B0001   | 系统错误     | 显示错误提示    |

> 具体错误码定义参见后端 `CommonErrorCode` 枚举。

### 3.4 分页结构对照

**前端分页参数**:

```typescript
interface PaginatingCommonParams {
  current: number;  // 当前页码
  size: number;     // 每页大小
  total: number;    // 总记录数
}

interface PaginatingQueryRecord<T> extends PaginatingCommonParams {
  records: T[];     // 数据列表
}
```

**后端分页结构** (`Paging<T>` 继承 MyBatis-Plus `Page<T>`):

```java
public class Paging<T> extends Page<T> {
    private long current;   // 当前页码
    private long size;      // 每页大小
    private long total;     // 总记录数
    private List<T> records; // 数据列表
}
```

**结论**: 分页结构完全一致，无需转换。

## 4. 基础能力建设

> 本章为新增核心内容，定义前后端对接的通用基础设施规范。

### 4.1 通用字段数据使用规范

#### 4.1.1 通用实体字段

后端所有业务实体均包含以下基础字段，前端通过 `Api.Common.CommonRecord<T>` 统一封装：

```typescript
// src/typings/api.d.ts
type CommonRecord<T = any> = {
  id: number;           // 主键
  createBy: string;     // 创建人
  createTime: string;   // 创建时间 (ISO 8601 格式)
  updateBy: string;     // 更新人
  updateTime: string;   // 更新时间
  status: EnableStatus; // 状态: '1'=启用, '2'=禁用
} & T;
```

#### 4.1.2 通用状态枚举

**启用状态** (`EnableStatus`):

```typescript
// src/typings/api.d.ts
type EnableStatus = '1' | '2';  // '1'=启用, '2'=禁用
```

前端常量定义 (`src/constants/business.ts`):

```typescript
export const enableStatusRecord: Record<Api.Common.EnableStatus, App.I18n.I18nKey> = {
  '1': 'page.manage.common.status.enable',
  '2': 'page.manage.common.status.disable'
};

export const enableStatusOptions = transformRecordToOption(enableStatusRecord);
```

使用规范：

- 所有列表页的 `status` 列，统一使用 `<ASwitch />` 或 `<Tag />` 渲染
- 状态变更直接调用 `update` 接口修改 `status` 字段

#### 4.1.3 布尔字段

后端使用 `Boolean` 类型（如 `state`），前端直接使用 `<ASwitch />`：

```vue
<ASwitch
  v-model:checked="model.state"
  :checked-value="true"
  :un-checked-value="false"
/>
```

#### 4.1.4 时间字段

后端返回 `LocalDateTime` 的 ISO 8601 字符串，前端统一使用 `dayjs` 格式化：

```typescript
import dayjs from 'dayjs';

// 表格列渲染
const formatDate = (value: string) => dayjs(value).format('YYYY-MM-DD HH:mm:ss');
```

#### 4.1.5 通用搜索参数

```typescript
// src/typings/api.d.ts
type CommonSearchParams = Pick<Common.PaginatingCommonParams, 'current' | 'size'>;
```

所有列表搜索参数应继承 `CommonSearchParams`，包含分页字段。

### 4.2 后端枚举获取及使用规范

#### 4.2.1 后端枚举体系

后端枚举必须遵循以下规范：

1. **实现 `BaseEnum<T>` 接口**
2. **标注 `@AppEnum(code = "xxx")` 注解**

```java
// 后端枚举示例
@Getter
@AllArgsConstructor
@AppEnum(code = "ConfigValueType")
public enum ConfigValueType implements BaseEnum<Integer> {
    TEXT(1, "文本"),
    FILE(2, "文件");

    @EnumValue
    private final Integer code;
    private final String desc;

    @JsonValue
    public String getJsonCode() {
        return String.valueOf(code);
    }
}
```

后端返回的枚举数据结构：

```json
[
  { "code": 1, "desc": "文本", "name": "TEXT" },
  { "code": 2, "desc": "文件", "name": "FILE" }
]
```

#### 4.2.2 后端枚举查询接口

后端自动提供两个接口（由 `carlos-spring-boot-starter-web` 模块提供）：

| 接口     | 方法  | 路径           | 描述                 |
|--------|-----|--------------|--------------------|
| 所有枚举字典 | GET | `/app/enums` | 获取全部枚举字典列表         |
| 单个枚举详情 | GET | `/app/enum`  | 参数 `name`，获取指定枚举详情 |

> **注意**：需在 `application.yml` 中开启枚举扫描功能。

#### 4.2.3 前端枚举基础设施（推荐建设）

**Step 1: 补充枚举类型定义**

```typescript
// src/typings/enum.d.ts
declare namespace Enum {
  interface EnumItem {
    code: string | number;
    desc: string;
    name: string;
  }
}
```

**Step 2: 创建枚举缓存 Store**

```typescript
// src/store/modules/enum.ts
import { defineStore } from 'pinia';
import { fetchGetEnumInfo } from '@/service/api';

export const useEnumStore = defineStore('enum-store', {
  state: () => ({
    cache: {} as Record<string, Enum.EnumItem[]>
  }),

  getters: {
    getEnumItems: (state) => (name: string): Enum.EnumItem[] => {
      return state.cache[name] || [];
    },
    getEnumOptions: (state) => (name: string): CommonType.Option<string>[] => {
      const items = state.cache[name] || [];
      return items.map(item => ({
        value: String(item.code),
        label: item.desc
      }));
    },
    getEnumDesc: (state) => (name: string, code: string | number): string => {
      const items = state.cache[name] || [];
      const found = items.find(item => String(item.code) === String(code));
      return found?.desc || String(code);
    }
  },

  actions: {
    async loadEnum(name: string) {
      if (this.cache[name]) return this.cache[name];
      const { data, error } = await fetchGetEnumInfo(name);
      if (!error && data) {
        this.cache[name] = data;
      }
      return this.cache[name] || [];
    },
    async loadEnums(names: string[]) {
      await Promise.all(names.map(name => this.loadEnum(name)));
    }
  }
});
```

**Step 3: 服务层补充枚举查询**

```typescript
// src/service/api/app.ts
import { request } from '../request';

/** 获取单个枚举详情 */
export function fetchGetEnumInfo(name: string) {
  return request<Array<{ code: string | number; desc: string; name: string }>>({
    url: '/app/enum',
    method: 'get',
    params: { name }
  });
}

/** 获取所有枚举字典 */
export function fetchGetAllEnums() {
  return request<Record<string, Array<{ code: string | number; desc: string; name: string }>>>({
    url: '/app/enums',
    method: 'get'
  });
}
```

**Step 4: 页面中使用**

```vue
<script setup lang="ts">
import { useEnumStore } from '@/store/modules/enum';

const enumStore = useEnumStore();

// 页面加载时获取枚举
onMounted(async () => {
  await enumStore.loadEnum('ConfigValueType');
});

// 表格列渲染枚举值
const columns = [
  {
    key: 'valueType',
    title: '值类型',
    customRender: ({ record }) => {
      return enumStore.getEnumDesc('ConfigValueType', record.valueType);
    }
  }
];

// 表单下拉选择
const valueTypeOptions = computed(() => enumStore.getEnumOptions('ConfigValueType'));
</script>

<template>
  <ASelect v-model:value="model.valueType" :options="valueTypeOptions" />
</template>
```

#### 4.2.4 前端枚举使用策略（二选一）

**策略 A: 前端硬编码（推荐用于不常变动的枚举）**

适用场景：性别、菜单类型、图标类型等固定业务枚举。

优点：

- 无需等待接口返回，页面渲染更快
- 可直接与 i18n 体系结合，支持多语言

实现：

```typescript
// src/constants/business.ts
export const configValueTypeRecord: Record<Api.SystemManage.ConfigValueType, App.I18n.I18nKey> = {
  '1': 'page.system.config.valueTypeOptions.text',
  '2': 'page.system.config.valueTypeOptions.file'
};

export const configValueTypeOptions = transformRecordToOption(configValueTypeRecord);
```

页面使用：

```vue
<template>
  <ASelect :options="translateOptions(configValueTypeOptions)" />
  <Tag>{{ $t(configValueTypeRecord[record.valueType]) }}</Tag>
</template>
```

**策略 B: 后端动态获取（推荐用于需要运营配置的枚举/字典）**

适用场景：系统配置类型、数据字典等可能动态扩展的枚举。

优点：

- 后端新增枚举值后，前端无需发版自动生效
- 统一管理，减少前后端重复定义

实现：使用上述 `useEnumStore`，在页面 `onMounted` 中加载。

**建议**：项目初期统一使用 **策略 A**（硬编码 + i18n），待需要动态扩展时切换到 **策略 B**（Store 动态获取）。两种策略可以共存。

            allowedMethods: "*"
            allowedHeaders: "*"

**单体应用配置**:

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
            .allowedOriginPatterns("http://localhost:*", "http://127.0.0.1:*")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .exposedHeaders("Authorization")
            .allowCredentials(true)
            .maxAge(3600);

}
```

### 2.3 密码加密

Carlos Framework 后端如使用 SM4 国密算法，前端需相应处理：

```typescript
// src/utils/crypto.ts
import { sm4 } from 'sm-crypto';

const SM4_KEY = 'your-sm4-key'; // 从环境变量或配置接口获取

export function encryptPassword(password: string): string {
  return sm4.encrypt(password, SM4_KEY);
}
```

### 2.4 Token 刷新机制

前端已实现自动刷新逻辑，后端需保证：

1. **Token 有效期**: access_token 建议 2 小时，refresh_token 建议 7 天
2. **刷新接口**: 使用 refresh_token 换取新的 access_token
3. **并发控制**: 多个请求同时触发刷新时，只执行一次刷新

## 风险评估与应对

### 风险 1: 枚举值前后端类型不一致

**风险等级**: 中
**影响范围**: 枚举显示和表单提交
**应对措施**:

- 后端枚举如使用 `@JsonValue` 返回 String，前端类型也应定义为字符串字面量类型（如 `'1' | '2'`）
- 后端枚举如未使用 `@JsonValue`，Jackson 可能序列化为枚举名（如 `"TEXT"`），需前后端对齐
- 建议后端所有枚举统一添加 `@JsonValue` 返回 `String.valueOf(code)`

### 风险 2: 枚举扫描包路径遗漏

**风险等级**: 中
**影响范围**: 枚举字典不完整
**应对措施**:

- 在 `application.yml` 中集中维护 `scan-package` 列表
- 新增业务模块时，同步追加扫描包路径
- 启动日志中检查 `Scan 'BaseEnum' subClass, count= x` 确认扫描数量

### 风险 3: Token 刷新并发问题

**风险等级**: 中
**影响范围**: 用户体验
**应对措施**:

- 前端已实现请求队列，确保刷新时其他请求等待
- 后端确保 refresh_token 只能使用一次

### 风险 4: 菜单数据与前端路由不匹配

**风险等级**: 中
**影响范围**: 页面访问
**应对措施**:

- 建立菜单-路由映射规范文档
- 组件路径统一命名规范
- 添加路由存在性检查接口
