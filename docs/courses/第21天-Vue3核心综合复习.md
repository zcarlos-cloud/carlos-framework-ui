## 理论学习

### 核心知识点 — 第二阶段全景回顾

#### 1. Composition API 的本质：函数式组装

Vue 3 的 Composition API 不是"新语法"，而是**新的代码组织方式**。它把原本分散在 `data`、`methods`、`computed`、`watch` 中的逻辑，按**功能维度**重新组织成一个个函数。

```typescript
// Options API — 按选项类型组织（Vue 2 风格）
export default {
  data() { return { count: 0 } },
  computed: { double() { return this.count * 2 } },
  methods: { increment() { this.count++ } },
  watch: { count(newVal) { console.log(newVal) } }
}

// Composition API — 按功能逻辑组织（Vue 3 风格）
function useCounter() {
  const count = ref(0);
  const double = computed(() => count.value * 2);
  function increment() { count.value++; }
  watch(count, (newVal) => { console.log(newVal); });
  return { count, double, increment };
}
```

**为什么这样更好？**
- 相同功能的代码聚合在一起（阅读一个功能只需看一个函数）
- 逻辑可复用（`useCounter()` 可以在任意组件中调用）
- 更好的 TypeScript 类型推断（函数返回值天然有类型）

#### 2. 响应式系统的核心模型

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   ref(0)    │────▶│  Proxy 包装  │────▶│  依赖收集   │
│  .value = 1 │◀────│  触发更新   │◀────│  effect执行 │
└─────────────┘     └─────────────┘     └─────────────┘
```

- **`ref`**：包装任意值，返回 `{ value: T }` 对象。适合基本类型和需要替换整个对象的场景。
- **`reactive`**：包装对象，返回 Proxy 代理。适合对象/数组且只修改属性的场景。
- **`computed`**：缓存的计算属性，依赖不变不重新计算。类比 Java 的懒加载 getter。
- **`watch`**：监听响应式数据变化，执行副作用。类比 Java 的 `PropertyChangeListener`。
- **`watchEffect`**：自动追踪依赖，执行副作用。不需要显式指定监听目标。

#### 3. `<script setup>` 的编译真相

```vue
<script setup lang="ts">
const count = ref(0);
</script>
```

编译后等价于：

```typescript
export default {
  setup() {
    const count = ref(0);
    return { count }; // 自动暴露给模板
  }
}
```

**`<script setup lang="tsx">` 的特殊性**：
- 支持在 `customRender` 中写 TSX（React 风格的 JSX）
- 需要 `jsx: 'preserve'` 和 `jsxImportSource: 'vue'` 的 tsconfig 配置
- 在 AntDV Table 的 `customRender` 中非常实用

#### 4. SFC 导入顺序的铁律

```typescript
// 1. 类型导入（编译时消除，不生成运行时代码）
import type { MaybeRef } from 'vue';

// 2. 第三方库（Vue, Pinia, Ant Design Vue, VueUse）
import { computed, ref, watch } from 'vue';
import { useElementSize } from '@vueuse/core';

// 3. 内部模块（按 @/store/ → @/hooks/ → @/utils/ → @/locales/ 排序）
import { useAppStore } from '@/store/modules/app';
import { $t } from '@/locales';
import { jsonClone } from '@sa/utils';

// 4. 同目录相对路径（./modules/xxx.vue）
import UserSearch from './modules/user-search.vue';
```

**为什么要这样排序？**
- 类型导入在最前：明确告知编译器这些只在类型检查时使用
- 第三方库随后：明确区分"外部依赖"和"内部代码"
- 内部模块按层级排序：store（全局状态）→ hooks（逻辑复用）→ utils（工具函数）→ locales（国际化）
- 相对路径最后：同一模块的局部依赖，放在最底部避免视觉干扰

### Java 思维类比

| 前端概念 | Java 类比 | 连接说明 |
|---------|----------|---------|
| Composition API | 静态工具方法 + 构造函数 | 像写 `UtilityClass` 一样写逻辑，但自动获得响应式能力 |
| `ref(0)` | `AtomicInteger` | 包装一个值，引用不变但值可变，需要 `.value` 解包 |
| `reactive({})` | `ObservableMap` / `BeanWrapper` | 对象属性自动追踪变化，不需要显式 `.value` |
| `computed()` | 懒加载 getter + 缓存 | 像 `@Cacheable` 的方法，依赖不变直接返回缓存值 |
| `watch()` | `PropertyChangeListener` | 监听特定属性的变化，执行回调 |
| `watchEffect()` | `Observer` 模式自动订阅 | 自动追踪函数内使用的响应式数据，任一变化都触发 |
| `<script setup>` | `final` 类 + 构造参数注入 | 编译时自动暴露变量给模板，减少样板代码 |
| `defineProps<{...}>` | 接口参数声明 + `@NotNull` | 类型化声明组件的"构造参数"，编译时校验 |
| `defineEmits<{}>` | 观察者模式 `notifyObservers()` | 类型化声明组件可以发出的事件 |
| 插槽 `slot` | 模板方法模式 `abstract render()` | 父组件定义框架，子组件填充内容 |
| `provide/inject` | Spring `@Autowired`（跨层级） | 跨层级依赖注入，避免 props 逐层传递 |
| `useTable()` | Service 层封装 | 把分页/加载/搜索逻辑封装成可复用的"服务" |
| `shallowRef()` | 浅拷贝 + 引用替换 | 只追踪引用变化，不追踪深层属性变化，性能优化 |

### 超越类比 — 前端独有的设计哲学

> **Java 的类比是桥梁，但前端有 Java 无法比拟的独特优势。**

1. **响应式是"自动的"，不是"手动的"**
   - Java 中要实现属性变化自动通知，需要写 `PropertyChangeSupport`、注册监听器、手动触发 `firePropertyChange()`。
   - Vue 3 中，`ref` 和 `reactive` 通过 Proxy 拦截 **自动**完成依赖收集和通知。你不需要写任何观察者注册代码。
   - **为什么前端能做到？** JavaScript 是动态语言，可以在运行时拦截属性访问。Java 的强类型编译时模型无法做到这一点（除非用 AspectJ 或字节码注入）。

2. **虚拟 DOM 是"声明式 UI"的核心**
   - Java Swing/JavaFX 中，你需要手动操作 DOM（`panel.add(component)`、`label.setText()`）。
   - Vue 中，你声明 "UI 应该长什么样"（template），框架自动计算差异并更新。这就是 **声明式 vs 命令式** 的本质区别。
   - **为什么声明式更好？** 状态与 UI 自动同步，你只需关心"数据是什么"，不需要关心"如何更新 UI"。

3. **`<script setup>` 是"编译时魔法"**
   - Java 没有编译时宏或语法糖（Lombok 除外）。
   - Vue 的 `<script setup>` 在编译阶段自动推导组件选项、自动暴露变量、自动处理类型。这是 **编译器增强框架** 的典范。
   - **为什么需要编译器？** 因为 Vue 要同时满足：1) 模板语法简洁性；2) TypeScript 类型完整性；3) 运行时性能。没有编译器，三者无法兼得。

4. **Composable 是"更灵活的 Service 层"**
   - Java 的 Service 是类级别的，需要通过依赖注入框架（Spring）管理生命周期。
   - Vue 的 Composable 是函数级别的，随组件创建而创建，随组件销毁而销毁（通过 `onScopeDispose`）。更轻量、更灵活、更易于测试。
   - **为什么更灵活？** 函数比类更容易组合（你可以在一个 `setup` 中调用多个 `useXxx`），也更容易单元测试（纯函数输入输出）。

#### 子任务3：实现表格数据加载（不使用 `useTable`，手写理解原理）

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue';
import { request } from '@/service/request';

// 数据状态
const data = ref<Api.UserManage.User[]>([]);
const loading = ref(false);

// 分页状态
const pagination = ref({
  current: 1,
  pageSize: 10,
  total: 0
});

// 搜索参数
const searchParams = ref<Api.UserManage.UserSearchParams>({
  current: 1,
  size: 10,
  userName: undefined,
  status: undefined
});

// 加载数据
async function loadData() {
  loading.value = true;
  try {
    const res = await request<Api.Common.PaginatingCommonParams & { records: Api.UserManage.User[] }>({
      url: '/user/list',
      method: 'get',
      params: searchParams.value
    });
    
    if (res.data) {
      data.value = res.data.records || [];
      pagination.value.total = res.data.total || 0;
    }
  } catch (error) {
    console.error('加载数据失败:', error);
    // 实际项目中应使用统一的错误处理
  } finally {
    loading.value = false;
  }
}

// 初始化加载
onMounted(() => {
  loadData();
});
</script>
```

**技术要点**：
- `ref` 用于基本类型和需要替换的对象（`data.value = []`）
- `onMounted` 用于初始化加载（类比 Java `@PostConstruct`）
- `try/catch/finally` 确保 loading 状态正确复位
- 使用 `request<T>` 泛型确保响应类型安全

#### 子任务4：分页逻辑

```typescript
// 分页切换
async function handlePageChange(current: number, pageSize: number) {
  pagination.value.current = current;
  pagination.value.pageSize = pageSize;
  searchParams.value.current = current;
  searchParams.value.size = pageSize;
  await loadData();
}

// 搜索（回到第一页）
async function handleSearch() {
  pagination.value.current = 1;
  searchParams.value.current = 1;
  await loadData();
}

// 重置搜索
function handleReset() {
  searchParams.value = {
    current: 1,
    size: 10,
    userName: undefined,
    status: undefined
  };
  pagination.value.current = 1;
  loadData();
}
```

**技术要点**：
- 分页切换时同步更新 `pagination` 和 `searchParams`
- 搜索时重置到第一页（用户体验）
- 重置时恢复初始状态（使用 `undefined` 而非 `null`，因为 AntDV Form 的 `v-model` 对 `undefined` 有特殊处理）

#### 子任务5：搜索表单（使用 `reactive`）

```vue
<!-- modules/user-search.vue -->
<script setup lang="ts">
import { reactive } from 'vue';

interface Props {
  model: Api.UserManage.UserSearchParams;
}

const props = defineProps<Props>();
const emit = defineEmits<{
  search: [];
  reset: [];
}>();

// 本地表单状态（用 reactive，因为表单是对象且修改属性）
const formState = reactive({ ...props.model });

function handleSearch() {
  // 将本地状态同步回父组件
  Object.assign(props.model, formState);
  emit('search');
}

function handleReset() {
  Object.assign(formState, { userName: undefined, status: undefined, userGender: undefined });
  emit('reset');
}
</script>

<template>
  <AForm layout="inline" :model="formState">
    <AFormItem label="用户名">
      <AInput v-model:value="formState.userName" placeholder="请输入用户名" />
    </AFormItem>
    <AFormItem label="状态">
      <ASelect v-model:value="formState.status" placeholder="请选择状态">
        <ASelectOption value="1">启用</ASelectOption>
        <ASelectOption value="2">禁用</ASelectOption>
      </ASelect>
    </AFormItem>
    <AFormItem>
      <AButton type="primary" @click="handleSearch">搜索</AButton>
      <AButton @click="handleReset">重置</AButton>
    </AFormItem>
  </AForm>
</template>
```

**技术要点**：
- 使用 `reactive` 管理表单对象（属性多，修改频繁）
- `v-model:value` 是 AntDV 的语法（注意不是 `v-model`）
- 使用 `Object.assign` 同步状态（避免破坏响应式引用）

**为什么用 `reactive` 而不是 `ref`？**
- 表单是对象，属性多且修改频繁。`reactive` 不需要 `.value`，代码更简洁。
- 但要注意：不能用 `formState = {...}` 替换整个对象（会失去响应式），必须用 `Object.assign`。

#### 子任务6：编辑弹窗（使用 `useBoolean` 组合）

```vue
<!-- modules/user-edit-modal.vue -->
<script setup lang="ts">
import { ref, watch } from 'vue';
import { useBoolean } from '@sa/hooks';

interface Props {
  visible: boolean;
  operateType: 'add' | 'edit';
  rowData?: Api.UserManage.User | null;
}

const props = defineProps<Props>();
const emit = defineEmits<{
  'update:visible': [value: boolean];
  submit: [];
}>();

const { bool: confirmLoading, setTrue: startLoading, setFalse: stopLoading } = useBoolean(false);

const formState = ref<Partial<Api.UserManage.User>>({});

// 监听打开弹窗时初始化表单
watch(
  () => props.visible,
  (visible) => {
    if (visible) {
      if (props.operateType === 'edit' && props.rowData) {
        formState.value = { ...props.rowData };
      } else {
        formState.value = {};
      }
    }
  }
);

async function handleSubmit() {
  startLoading();
  try {
    const url = props.operateType === 'add' ? '/user/add' : '/user/update';
    await request({ url, method: 'post', data: formState.value });
    emit('update:visible', false);
    emit('submit');
  } finally {
    stopLoading();
  }
}
</script>
```

**技术要点**：
- `useBoolean` 封装布尔状态（`true`/`false` + `setTrue`/`setFalse`）
- `watch` 监听 `visible` 变化，在打开时初始化表单数据
- 使用 `defineEmits` 的数组语法（Vue 3.4+ 推荐）

#### 子任务7：表格列配置（使用 `computed`）

```typescript
const columns = computed(() => [
  {
    title: '用户名',
    dataIndex: 'userName',
    key: 'userName',
    align: 'center'
  },
  {
    title: '昵称',
    dataIndex: 'nickName',
    key: 'nickName',
    align: 'center'
  },
  {
    title: '状态',
    dataIndex: 'status',
    key: 'status',
    align: 'center',
    customRender: ({ record }: { record: Api.UserManage.User }) => {
      const statusMap = {
        '1': { color: 'success', text: '启用' },
        '2': { color: 'warning', text: '禁用' }
      };
      const status = statusMap[record.status];
      return <Tag color={status.color}>{status.text}</Tag>;
    }
  },
  {
    title: '操作',
    key: 'operate',
    align: 'center',
    customRender: ({ record }: { record: Api.UserManage.User }) => (
      <div class="flex-center gap-8px">
        <Button type="primary" ghost size="small" onClick={() => handleEdit(record.id)}>
          编辑
        </Button>
        <Popconfirm title="确认删除？" onConfirm={() => handleDelete(record.id)}>
          <Button danger size="small">删除</Button>
        </Popconfirm>
      </div>
    )
  }
]);
```

**技术要点**：
- `computed` 缓存列配置（避免每次渲染重新创建）
- `customRender` 使用 TSX（需要在 `<script setup lang="tsx">` 中）
- 标签使用 PascalCase（`<Tag>`、`<Button>`）
- 使用 UnoCSS 原子类（`flex-center gap-8px`）

**为什么 `columns` 用 `computed`？**
- 如果列配置依赖响应式数据（如语言切换），`computed` 会自动重新计算。
- 即使当前不依赖外部状态，`computed` 也能避免每次渲染创建新数组，减少不必要的 diff。

## 今日重点记忆卡

| 概念 | 一句话 | Java类比 | 前端独有 |
|------|--------|---------|---------|
| `ref` | 包装任意值的响应式容器，通过 `.value` 读写 | `AtomicInteger` | Proxy 自动拦截，无需手动通知 |
| `reactive` | 包装对象的响应式代理，直接访问属性 | `ObservableMap` | 深层属性自动追踪 |
| `computed` | 缓存的计算属性，依赖不变直接返回 | 懒加载 getter + `@Cacheable` | 自动追踪依赖，无需显式声明监听 |
| `watch` | 监听特定响应式数据，执行副作用 | `PropertyChangeListener` | 可监听多个源，支持深层监听 |
| `watchEffect` | 自动追踪函数内使用的响应式数据 | `Observer` 自动订阅 | 无需指定监听目标，自动收集依赖 |
| `<script setup>` | 编译时自动暴露变量给模板 | `final` 类 + 构造注入 | 编译器语法糖，运行时零开销 |
| `defineProps` | 类型化声明组件的输入参数 | 接口参数 + `@NotNull` | 编译时类型检查，运行时自动暴露 |
| `defineEmits` | 类型化声明组件可发出的事件 | 观察者模式 `notifyObservers()` | 数组语法支持命名元组参数 |
| `defineModel` | 双向绑定的语法糖（props + emits） | `PropertyEditor` + 事件 | Vue 3.4 宏，编译时展开 |
| `effectScope` | 管理多个副作用的生命周期 | `try-with-resources` | 组件卸载时自动停止所有副作用 |
| Composable | 可复用的响应式逻辑函数 | Service 层方法 | 函数级别，随组件创建/销毁，更轻量 |
| `shallowRef` | 只追踪引用变化的 ref | 浅拷贝 + 引用替换 | 大数据对象性能优化，避免深层响应式 |
| TSX | 在 Vue 中写 JSX | 无直接类比 | 模板语法之外的渲染方式，适合动态渲染 |
| `generic` | Vue 3.3+ 泛型组件语法 | Java 泛型类 | 编译时保留类型，支持类型安全的数据流 |
