# 前端学习路线：Java 工程师转型现代前端开发

> **目标学员**: 有 HTML/CSS/Vue2 基础、熟悉 Java/Spring Boot 生态、长期未接触前端的高级 Java 工程师
>
> **目标项目**: carlos-framework-ui（SoybeanAdmin AntDesign 版本）
>
> **技术栈**: Vue 3.5 + Vite 7 + TypeScript 5.9 + Ant Design Vue 4 + Pinia 3 + UnoCSS 66 + ECharts 6 + Vue Router 4
>
> **底层标准**: `docs/EXTREME-STANDARDS.md`、`docs/前端开发规范.md`

---

## 核心理念

每一行代码都要经得起"为什么这样写"的拷问。我们追求的不是写完，而是写对、写好、写精。

1. **从已知到未知，但不止步于类比** — 先用 Java 思维建立连接，然后超越类比，理解前端独有的设计哲学
2. **从项目中来，到规范中去** — 所有示例提取自 `carlos-framework-ui` 真实代码，但不止于"这样写能跑"，而是"这样写为什么比那样写更好"
3. **每天一课，每日一练，每练一评** — 理论学习 + 动手练习 + 规范评审（对照项目标准逐条检查）
4. **渐进深入，但深度不妥协** — 第1天就开始讲 TypeScript strict 模式，不是等到"基础打好了"再讲
5. **写三遍** — 第一遍能跑，第二遍规范，第三遍精益求精

## 一、学习策略总览

### 1.1 认知转换：Java vs 现代前端

| Java 概念                  | 前端对应概念                    | 类比说明           |
|--------------------------|---------------------------|----------------|
| Maven/Gradle             | pnpm + Vite               | 依赖管理 + 构建工具    |
| Spring IoC 容器            | Vue 3 运行时 + 组合式 API       | 依赖注入 → 组合式函数注入 |
| POJO/Entity              | TypeScript Interface/Type | 类型定义与数据建模      |
| Service 层                | Pinia Store               | 业务逻辑与状态管理      |
| Controller 层             | Vue 组件 + Vue Router       | 接收用户输入、路由分发    |
| MyBatis Mapper           | API Service 层             | 后端接口调用封装       |
| application.yml          | .env + vite.config.ts     | 环境配置与构建配置      |
| Lombok                   | Vue `<script setup>` + 宏  | 减少样板代码         |
| Jackson 序列化              | TypeScript 类型 + API 类型声明  | 前后端数据契约        |
| JUnit                    | Vitest / 浏览器 DevTools     | 单元测试与调试        |
| `final` 变量               | `const` / `let`           | 块级作用域声明        |
| Lambda 表达式               | 箭头函数 `() => {}`           | 匿名函数简写         |

## 二、第一阶段：现代前端基础回顾（第1-7天）

### 第1天：ES6+ 快速回顾 — 从 Java 视角看现代 JavaScript

**学习目标（3层）**：

- **能用**: 理解 let/const、箭头函数、解构、模板字符串、Promise、async/await、模块化
- **规范**: 统一使用 `const`，仅在必要时用 `let`，禁止 `var`
- **极致**: 理解 JS 原型链与 Java 继承的本质差异

**Java 类比**：

- `let`/`const` ≈ Java `final` 变量声明（作用域块级）
- 箭头函数 `() => {}` ≈ Java Lambda 表达式
- 解构 `{a, b} = obj` ≈ Java 记录解构（record pattern）
- Promise ≈ Java `CompletableFuture`
- async/await ≈ Java `CompletableFuture.thenApply` 的语法糖
- 模块化 `import/export` ≈ Java `import` + `public class`

**carlos-framework-ui 源码阅读**: `src/utils/common.ts` 中的工具函数（箭头函数、解构、展开运算符）

**练习任务**：

- **能用**: 用 ES6+ 重写一个传统 JS 函数
- **规范**: 统一使用 `const`，添加 JSDoc 注释
- **极致**: 分析解构赋值编译后的代码，理解性能差异

| Vue 2         | Vue 3                       | 说明                  |
|---------------|-----------------------------|---------------------|
| Options API   | Composition API             | 类配置 → 函数组合          |
| `data()`      | `ref()` / `reactive()`      | POJO 字段 → 响应式包装器    |

| Vuex          | Pinia                       | Spring 状态管理         |
| 全局事件总线        | `mitt` / Pinia              | 消息中间件               |
| 生命周期钩子        | `onMounted()` 等             | `@PostConstruct` 风格 |
| `v-model`     | 支持多个 + 自定义修饰符               | 双向绑定增强              |

```vue
defineOptions({ name: 'App' });

// 5. 逻辑代码
const appStore = useAppStore();
const antdLocale = computed(() => antdLocales[appStore.locale]);
</script>

<template>
  <ConfigProvider :theme="themeStore.antdTheme">
    <AppProvider><RouterView class="bg-layout" /></AppProvider>
  </ConfigProvider>
</template>

<style scoped></style>
```

## 十二、常见问题（Java 工程师特供）

### Q1: 为什么 Vue 3 不再用 `this`？

> Composition API 像写静态工具方法，通过参数和返回值交互，不需要 `this` 上下文。更清晰、更易测试、更好复用。

### Q2: `ref` 和 `reactive` 到底用哪个？

> - 基本类型或需要替换整个对象：用 `ref`（必须 `.value`）
> - 对象/数组且只修改属性：用 `reactive`（无需 `.value`）
> - 项目中统一风格：看已有代码，`ref` 使用更多

### Q3: TypeScript 类型报错看不懂怎么办？

> 1. 把鼠标悬停在报错处，看提示信息
> 2. 给变量显式标注类型
> 3. 使用 `as` 类型断言（临时绕过）
> 4. 逐步理解，不要畏惧

### Q4: 为什么 import 要区分 `type`？

> `import type { Xxx }` 只在编译时使用，不会生成运行时代码。类似 Java 的泛型擦除。

### Q5: 怎么调试 Vue 组件？

> 1. 安装 Vue DevTools 浏览器插件
> 2. 使用 `console.log()`（简单直接）
> 3. VS Code 断点调试（配置 launch.json）

### Q6: UnoCSS 类名记不住？

> 1. 安装 UnoCSS VS Code 插件，有智能提示
> 2. 查阅 [Windicss 速查表](https://windicss.org/)
> 3. 记住最常用的 20 个类即可

### Q7: 如何快速看懂一个 Vue 组件？

> 按这个顺序：1) 看 `template` 结构 → 2) 看 `script setup` 中的状态定义 → 3) 看方法逻辑 → 4) 看样式（通常是空的或用 UnoCSS）

## 十六、学习方法论

1. **先读源码再动手** — 每天先读 `carlos-ui` 对应功能的源码，理解设计思路
2. **用 Java 思维类比** — 遇到新概念时，先想 Java 中对应的模式
3. **每天一个可运行 Demo** — 不要只看不练，每天至少写出一个能跑起来的小功能
4. **记录笔记** — 将每天学到的知识点整理到个人笔记中
5. **写三遍** — 第一遍能跑，第二遍规范，第三遍精益求精
6. **问问题** — 遇到不理解的地方随时提问

---

> **最后寄语**：作为 Java 工程师，你已经具备了面向对象、设计模式、分层架构的思维。Vue 3 的 Composition API 本质上就是"函数式组装"，Pinia 就是"前端 Service 层"，API 层就是"前端 Mapper"。把这些概念映射到你熟悉的后端世界，学习曲线会平滑很多。加油！
